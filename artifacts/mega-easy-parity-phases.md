# خريطة مطابقة Mega ↔ Easy — ما تمّ وما يتبقى (مراحل)

**تاريخ:** 2026-09-15  
**مصادر الأدلة:** `mega-report-parity-tracker.md` · `mega-inv-screens-parity.md` · `mega-sales-purchase-icons-parity.md` · `mega-report-menu/` · `mega-invoice-create/` · `mega-inv-screens/` · حي `km.mega-cash.net`  
**تنبيه مهم:** حالة `status: done` في `erp-navigation.ts` تعني **وجود شاشة/مسار** في إيزي — **ليست** مطابقة سلوكية كاملة لميجا.

---

## خلاصة سريعة

| الطبقة | مطابقة Mega؟ | ملاحظات |
|--------|--------------|---------|
| قائمة التنقل (~390 عنصر) | هيكل شبه مكتمل | أيقونات/مسارات موجودة؛ العمق يختلف |
| تقارير (أعمدة بعد عرض/PDF) | موجات P0–10 مغلقة منهجياً | أغلب الفلاتر `partial`؛ بعض blocked على حساب test |
| مخازن (12 أيقونة) | عمق قوي | تبويبات صنف + قوائم/فلاتر/اعتماد؛ حدود صدق موثّقة |
| فواتير بيع/شراء — مسارات الأيقونات | مطابقة | `/new` منفصل عن القائمة + نقدي vs آجل |
| فواتير — حفظ/اعتماد ↔ مخزن | مطابقة حديثة | حفظ = مسودة بلا أثر؛ اعتماد = مخزن+قيود؛ خدمة بلا مخزن |
| فواتير — نموذج عميق (تبويبات/حقول/قائمة) | **جزئي كبير** | أدناه مرحلة A |
| مردودات / طلبات / خزينة / بنك / قيود | جزئي | تحتاج نفس عمق الفاتورة |
| صلاحيات شاشة×فعل كمصفوفة ميجا | موجود إيزي | عمق المطابقة غير مدقّق حيّاً كموجة مستقلة |
| «أنيميشن» كحركة واجهة | غير هدف ميجا | ميجا ASP.NET؛ المطلوب انتقالات حالات مستند لا حركات زخرفية |

## 1) ما طابقنا فعلياً (بمرجع Mega)

### أ) تقارير
- منهجية: دليل PDF/فلاتر → تسميات → إعادة تشكيل صفوف → صدق (`mega-report-parity-method.md`).
- P0: ميزان / أستاذ عام / كشف حساب / كشف عميل بالأصناف (أعمدة؛ بعض فلاتر كشف الحساب لسه).
- موجات 1–10: أعمدة معظم التقارير من PDF ميجا؛ الفلاتر غالباً `partial` (ميجا أغنى).
- متبقٍ blocked/صدق: أعمار أصناف، أعمار ديون موردين (PDF)، أستاذ مساعد كامل، دفتر يومية كقائمة قيود، تجميع/تذييل مندوبين، حقول HR/أصول ناقصة في سكيمة إيزي.

### ب) مخازن (مرجع `mega-inv-screens/`)
ترتيب الأيقونات + حقول/فلاتر/حفظ·اعتماد·فك·إلغاء + تعليقات + تغيير أسعار بطبقات + باركود وحدة + مسلسل أول مدة — موثّق في `mega-inv-screens-parity.md`.

**تبويبات صنف ميجا (`Item.aspx` TabContainer):**
| تبويب | محتوى ميجا | إيزي |
|-------|------------|------|
| TabPanel2 | بيانات أساسية / نوع / ضرائب / حدود سعر | موجود (بطاقة/أقسام) |
| TabPanel1 | أسعار متعددة (نوع سعر·عملة·خصم) | موجود عمق أسعار |
| TabPanel3 | وحدات إضافية + باركود وحدة | موجود |
| TabPanel4 | مكونات مجموعة/طقم | تبويب مكونات |
| TabPanel5 | أقل كمية/مكان بالمخزن | موجود |

### ج) فواتير بيع/شراء — الطبقة التي اكتملت
- خريطة الأيقونات والمسارات (`mega-sales-purchase-icons-parity.md`).
- **حفظ vs اعتماد** وأثر المخزن (مرجع حي Invoice/Cash/Receipt) — مطبّق في السيرفر والواجهة.
- على النموذج الحالي: أصناف + ضرائب فاتورة + مصروفات + تسوية دفع + طباعة بعد حفظ/اعتماد + إذن مخزن؛ مخزن على السطر؛ تشغيلة؛ سيريل؛ ض1–3؛ عروض.

## 2) فجوات العمق — «تبويب جوه تبويب / عرض / فلاتر»

هذا محور طلبك: ميجا غالباً **TabContainer + شبكات فرعية + فورم فلاتر قبل بحث**؛ إيزي غالباً **بطاقة واحدة طويلة أو DataTable ببحث بسيط**.

### فاتورة بيع ميجا (`/Sales/Invoice.aspx`) — بنية العرض
1. رأس: عملة·سعر صرف·فرع·عميل·مندوب·عنوان·تليفون·**نوع الاستلام (كلي/جزئي)**·استحقاق·تاريخ·مرجع·خزينة·بنك·**شركة شحن**·مركز تكلفة·**عميل/عنوان مؤقت**.
2. مناطق داخل المستند: **الأصناف | الضرائب | المصروفات | ملاحظات** (+ مجاميع ومديونية قبل/بعد).
3. سطر الصنف: مخزن·باركود·فئة·صنف·كمية·وحدة·تشغيلة·**كمية متاحة**·تكلفة متوقعة·**نوع السعر**·سعر·خصم %·خصم نقدي·ض1–3·آخر سعر·حدود سعر·ملاحظات سطر.
4. أسفل: مدفوع نقدي/بنكي · خيارات طباعة (بعد حفظ/اعتماد/إنجليزي/إذن مخزن/إيصال) · **حفظ** · **اعتماد** · **إضافة تعليق**.

### إيزي اليوم (`SalesInvoices.tsx`)
- عرض = بطاقات متتابعة (ليس تبويبات ميجا حرفياً) — مقبول وظيفياً لو الحقول كاملة.
- موجود بقوة: عميل·تاريخ·استحقاق·عملة/صرف·مخزن افتراضي·فرع·مركز تكلفة·نوع دفع·أصناف (مخزن سطر·كمية·سعر·خصم%·ض·دفعة·سيريل)·ضرائب/مصروفات·تسوية·حفظ/اعتماد·طباعات أساسية.
- **ناقص أو أضعف مقابل ميجا (أولوية مرحلة A):**
  - نوع الاستلام كلي/جزئي + أثر تسليم مرحلي على المخزن
  - مندوب / تليفون / رقم مرجع / حساب خزينة·بنك على الرأس (التسوية تغطي دفع جزئياً)
  - حساب شركة الشحن · عميل/عنوان مؤقت
  - كمية متاحة ظاهرة · نوع السعر · خصم نقدي سطر · حدود السعر
  - طباعة بالإنجليزية · طباعة كإيصال · إضافة تعليق على المستند
  - قائمة الفواتير: فلاتر ميجا (حالة تحصيل·تسليم·منطقة·مندوب·مدير·فرع عميل·استحقاق من/إلى·شركة شحن…) vs بحث DataTable عام

نفس الفجوة تقريباً على **فاتورة شراء** (`Receipt.aspx`) + قوائمها.

### تقارير — فلاتر vs أعمدة
- مسح حي: ~75 تقرير، أغناها ~38 فلتر (`accountingreports-sales`).
- إيزي: أعمدة غالباً من PDF؛ **سطح الفلاتر أضيق** من فورم ميجا (هذا سبب `filters: partial` الجماعي في المتتبع).
- أنماط عرض ميجا الناقصة غالباً: تجميع/تذييلات (مندوب·منطقة)، اختيارات «اخفاء التفاصيل / فصل كشوف / مستوى العرض / طريقة تجميع العملاء»، تصدير بتنسيق/بدون، محاذاة يسار·وسط·يمين.

### صلاحيات / مستخدمين
- إيزي: `UsersPermissions` + بوابات كيان/فعل.
- ميجا: مصفوفة شاشات×أفعال غنية — **لم تُغلق كموجة أدلة حيّة** مثل التقارير/المخازن؛ تحتاج تدقيق شاشة×شاشة.

### أنيميشن
- ميجا لا يعتمد حركات تسويقية؛ المطلوب في إيزي: انتقالات حالات (مسودة→معلق→معتمد→فك/إلغاء) وتغذية راجعة للحفظ — **ليس** مرحلة أنيميشن منفصلة.

## 3) المراحل المقترحة للشغل الجاي

رتّب حسب أثر تشغيلي يومي + أدلة Mega الجاهزة. كل مرحلة = أدلة → حقول/فلاتر/حالات → سيرفر → واجهة → صدق في المستند.

### مرحلة A — عمق مستند البيع/الشراء (P0 تشغيلي)
**الهدف:** نفس تسلسل ميجا داخل الفاتورة والقائمة (ليس فقط أيقونة + سحب مخزن).

| # | بند | مرجع Mega |
|---|-----|-----------|
| A1 | رأس الفاتورة الكامل (مندوب، مرجع، تليفون، خزينة/بنك رأس، شحن، مؤقت) | Invoice.aspx body — ✅ |
| A2 | سطر: كمية متاحة، نوع السعر، خصم نقدي، حدود السعر، فئة/باركود صريح | نفس — ✅ |
| A3 | نوع الاستلام كلي/جزئي + قواعد مخزن مرحلي | استلام كلي/جزئي — ✅ (`deliveredQuantity`) |
| A4 | تعليقات مستند + خيارات طباعة إنجليزي/إيصال | أزرار/checkboxes — ✅ |
| A5 | فلاتر قائمة الفواتير = فورم ميجا list | InvoicesList / ReceiptsList — ✅ |
| A6 | نفس الحزمة لمردود بيع/شراء ثم طلبات | Return* / *Order — ✅ حفظ=مسودة · اعتماد=مخزن+قيد للمردود · حقول رأس/سطر + فلاتر قائمة |

**مخرجات:** `0066_invoice_mega_a1_a5.sql` + تحديث `mega-sales-purchase-icons-parity.md`.

### مرحلة B — فلاتر التقارير الغنية (بعد ثبات الأعمدة)
- ابدأ بأغنى 10: `sales` · `purchases` · `grosscustomersalesbyitems` · `checks-*` · `salesorders` · `invoiceprofits` · `itemsprofits` · `inventorysummary` · `productionorders` · `payments`.
- لكل تقرير: انقل فلاتر `FILTERS-BY-REPORT.md` الناقصة فقط إن وُجد لها معنى بيانات في إيزي؛ وإلا سطر صدق.
- أغلق بقايا P0: نوع القيد / اعتمد بواسطة / checkboxes كشف الحساب؛ طريقة تجميع العملاء في الميزان إن اتضحت الدلالة.

### مرحلة C — إغلاق صدق التقارير + blocked
- حساب ميجا بصلاحيات أعلى: CreditsAges* · ItemAging · SubLedger بحساب · رؤوس GeneralJournalList.
- تجميع/تذييل مندوبين؛ تفاصيل أرباح فاتورة؛ حقول HR/أصول الناقصة في السكيمة أو إخفاؤها بصدق.

### مرحلة D — مستندات مالية وتشغيل بنفس منهج A
خزينة · بنك · شيكات · قيود يومية · سندات قبض/صرف · أقساط — تبويبات/فلاتر قائمة/حفظ·اعتماد من لقطات Mega حية (مجلدات capture جديدة تحت `artifacts/mega-finance-screens/`).

### مرحلة E — جهات اتصال / مندوبين / مناطق / أسعار عميل
شاشات Contacts + Reps: فلاتر قائمة، تبويبات بطاقة عميل، ربط مندوب بالفاتورة (يعتمد على A1).

### مرحلة F — إنتاج / أصول / HR (عمق شاشة وليس تقرير فقط)
أوامر تشغيل، خلطة/BOM عند البيع إن لزم، إهلاك/بيع أصل، حضور وراتب — دائماً بعد لقطة Mega لنفس الشاشة.

### مرحلة G — صلاحيات وخصائص عامة
مصفوفة شاشة×فعل كميجا؛ خصائص عامة تؤثر على الفاتورة (تنبيه vs منع نقص، طباعة افتراضية، اعتماد إلزامي…).

### خارج المراحل / متعمد سابقاً
- عدم إظهار اسم Mega في الواجهة.
- تفجير طقم تلقائي في البيع (مكونات جاهزة على الصنف؛ التفجير عند البيع مؤجّل).
- إنشاء صنف من نافذة التسوية حرفياً.
- أنيميشن زخرفي.

## 4) تعريف «مطابق» لكل شاشة مستند

لا تُعلَّم `done` إلا بعد:

1. خريطة حقول/أزرار/فلاتر من Mega (JSON أو لقطة).
2. نفس القيود المحاسبية/المخزنية عند حفظ vs اعتماد.
3. قائمة: نفس أبعاد الفلترة الأساسية (فرع·تاريخ·حالة·طرف·مسلسل…).
4. طرق العرض إن وُجدت في ميجا (تجميع، إخفاء تفاصيل، مستويات) — أو صدق صريح.
5. تعليق في ملف parity للشاشة.

## 5) اقتراح ترتيب تنفيذ عملي (سبرنتات تقنية)

1. **A1–A2 + A5** على فاتورة البيع ثم الشراء (أكبر فرق يومي للمستخدم).  
2. **A4** تعليقات/طباعة.  
3. **A3** استلام جزئي (أخطر محاسبياً — يحتاج سيناريو Mega مكتوب).  
4. **A6** مردودات وطلبات.  
5. **B** فلاتر تقارير Top-10.  
6. **D** خزينة/بنك/قيود.  
7. **C / E / F / G** حسب أولوية التشغيل عندك.
